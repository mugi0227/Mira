# Miraの任意Jev入力補助

会話の「意図」だけを分類する試験的な接続です。初期状態では無効です。入力した本文と、案件を選択中かどうかだけを送ります。予定一覧・会話履歴・人物一覧は送りません。日時、タイトル、制約、候補生成は既存の端末内処理に残します。

日本語精度と日本からの実応答時間は**未検証**です。この変更ではTypeSafeへ実リクエストを送っていません。日程登録を自動化する機能ではありません。

## 構成

`iOS → 自分のHTTPS Miraサーバー /v1/intent → TypeSafe /v1/systemone`

- Python 3.10以降。標準ライブラリのみで動き、WSGIアプリとして配備できます。
- `TYPESAFE_API_KEY`: サーバーだけで管理するTypeSafe APIキー。
- `MIRA_CLIENT_TOKEN`: この個人用Miraサーバーに接続するための32文字以上のランダムなASCIIトークン。iOSではKeychainに保存します。プロバイダーのAPIキーとは別です。
- `MIRA_JEV_MODEL`: 省略時`jev-1.13.0`。更新時の意図変化を検出するため、固定版のみ指定できます。

接続先、質問、モデル名をクライアントから自由に渡すAPIではありません。未認証・不正入力・12,000バイト超・過剰な呼び出しを拒否します。TypeSafeへの接続は2.5秒、iOSはリクエスト3秒・全体4秒で打ち切ります。両方でHTTPリダイレクトを拒否します。

## 起動・配備

秘密管理サービスまたはサーバーの環境変数に上記2つの資格情報を設定します。`.env`やキーをリポジトリへ保存しないでください。開発確認は`backend`ディレクトリで次を実行します。

```sh
python -m unittest discover -p "test_*.py" -v
python jev_proxy.py
```

開発サーバーは`127.0.0.1:8787`のみで待ち受けます。資格情報がない場合は起動しません。iOSはHTTPSを必須とするため、開発用HTTPを直接設定することはできません。

継続運用では開発サーバーを使わず、WSGI対応サーバーとTLSリバースプロキシを使用します。LinuxでGunicornを別途用意する場合の起動例は次です。

```sh
gunicorn --bind 127.0.0.1:8787 --workers 1 --threads 4 --timeout 10 'jev_proxy:create_application()'
```

HTTPSプロキシ側にも12KBのbody上限・短いrequest body受信timeout・同時接続数上限を設定します。アプリ内の60回/分の制限はプロセス単位なので、複数workerやreplicaにする場合は共有のrate limiterが必要です。本文、Authorizationヘッダー、URL query、upstreamエラー本文はアクセスログやAPMに記録しない設定にします。標準開発サーバーのアクセスログと本アプリのpayloadログは無効です。

これは**個人用の配備**です。複数利用者へ公開する際は利用者ごとの認証・失効・使用量制限を実装してください。共有トークンを配布する公開サービスとしては使わないでください。

iOSの「設定 → クラウドの入力補助」に、`https://自分のホスト/v1/intent`とMira用の接続トークンを入力します。説明を確認してスイッチをオンにし「設定を保存」で有効になります。設定を保存しても疎通確認は行いません。TypeSafe APIキーをiOSに入力しないでください。オフ操作は直ちに新しい呼び出しを止め、実行中の返答も反映しません。

## 判断の境界

TypeSafeのChoice確率とconfidenceがともに0.80以上のときだけ候補にします。0.80は初期の保守的な閾値であり、日本語での正答率を保証する数値ではありません。低信頼度、unknown、通信失敗、不正応答では端末の解釈をそのまま使います。

最初の導入範囲は、案件を選択していない入力を「誘いの相談」「候補探し」へ振り分けることです。既存案件の継続、明示的な変更や断りは端末の解釈を維持します。クラウドの回答だけでaddEvent/updateExisting/declineInvitationへ変更しません。分類が変わっても抽出済み日時や除外条件を捨てません。Jevのconfidenceを日時を含む解釈全体のconfidenceへ転用しません。

端末内に保存した下書きとMiraStoreの入力世代チェックで、中断や入力変更後の古い結果による上書きを防ぎます。入力が2,000文字またはUTF-8で8,000バイトを超える場合も端末内処理だけを使用します。

## 評価

`fixtures/intent-cases-ja.json`は24件の架空入力と期待値です。相談・仮定・否定・言い直し・入力途中・命令注入風の文章を含みます。`test_jev_proxy.py`と`MiraTests/JevIntentRouterTests.swift`は通信契約・失敗時の動作・統合境界をmockで確かめます。**fixtureが通ることはJevの分類精度を測ったことにはなりません。**

実利用前に独立した例文を追加し、既存の分類との比較をしてください。評価用と調整用を分け、正しい画面への到達率、相談を確定として扱う誤り、修正回数、不要な確認、p50/p95応答時間を記録します。評価ログは例文ID、期待ラベル、回答ラベル、モデル版、時間、confidenceだけに限定し、本人の生の予定や会話を収集しません。実入力を扱う場合は別途本人の選択と保存方針が必要です。

## データの扱い

このproxyは本文を永続化しません。ただし接続先の管理者は本文にアクセスでき、TypeSafe直接利用の保存条件は契約によります。No TrainingはZero Data Retentionを意味しません。必要な保持条件を満たす契約・サービス経路を確認してから有効にしてください。
