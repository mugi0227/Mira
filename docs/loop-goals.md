## 2. すでにあるもの（作り直さない）

| 構想の要素 | 既存の実装 | このループでの扱い |
|---|---|---|
| 自然文で頼む | `MiraChatView`（ホームの案内役ボタン）＋ `RuleBasedChatAgent` / Foundation Models エージェント。ツールは読む・提案するだけで、適用は本人がカード上で行う | **入口として使う。** 「自分の時間を増やしたい」系の依頼に応えるツールとカードを足す |
| 提案→適用→取り消し | 再配置案 `RebalanceProposal`（保存・適用前の再検証・見送り）、`captureCalendarUndo` による取り消し | **同じ作法に揃える。** 新しい提案も適用前に再検証し、取り消しは既存の Undo に載せる |
| 空き状況の共有 | `FriendAvailability` / `FriendShareCard`（朝・昼・夜の帯だけを画像で共有、タイトルは出さない） | **プライバシーを回帰テストで固定**し、文字で送る手段を足す |
| 通知 | `NotificationService` + `ReminderPlan`（返事・調整期限） | **提案通知を同じサービスに足す** |
| 余白の目標と配置 | 月間目標、自動配置、`MarginRecommendationEngine`、マイ余白タブ | 週次の目安はこの月間目標から按分する |

## 3. 範囲

対象: S1, S2, S4, S6, S7。
対象外（次ループ）: S5 フォロー・空き枠減少通知（バックエンドが必要）。

## 4. 受け入れシナリオ（機能ゴール）

`[D]` = `scripts/test-domain.py` で Linux でも走るドメインテスト、`[U]` = iOS 単体テスト（SwiftData を含む）、`[UI]` = XCUITest。

### S1 曖昧な意図から提案（チャット）
- チャットで「来週は自分の時間を増やしたい」と送ると、来週の自分時間を増やす**提案カード**が返る。`[UI]`
- カードには追加される枠の日時と増える時間数が出る。`[D]`
- カードの「この案で置く」1タップで余白が入る。他者が関わる予定（確定予定・調整候補）は1件も変わらない。`[U]`
- 置いた余白は既存の取り消し（Undo）で戻せる。`[U]`
- 空きが見つからないときは「見つからない」だけで終わらず、今ある自分時間の量と別の週の提案を返す。`[D]`
- 既存のチャットの振る舞い（予定追加・日程探し・断り文・バランス確認）は変わらない。既存テストが緑。`[U]`

### S2 提案は勝手に適用されず、通知で知らせる
- 来週の自分時間が週の目安を下回ると、能動的な提案がホームにカードで出る（`pending`）。カレンダーは変わらない。`[U]` `[UI]`
- 新しい能動的な提案ができ、通知が有効なら通知を予約する。通知は1日1件まで、22時〜8時は朝8時に回す。同じ週への提案は重複させない。`[D]`
- 「今回は見送る」は1タップで記録され、同じ週には再提示しない。`[U]`
- 適用直前に状況が変わっていたら、ぶつかる枠は置かずに伝える。`[D]` `[U]`
- 通知の設定文言は、提案も知らせることが分かる表現にする。

### S4 空き状況の共有とプライバシー
- `FriendAvailability` と共有文には、どの予定タイトル・余白の種類名・カレンダー名も含まれない。`[D]`
- これから2週間の空いている帯を、文字でも送れる（例：「9/12(土) 昼・夜」）。`[D]` `[UI]`

### S6 傾向に沿った提案
- 提案の採用・見送りの記録が3件以上あると、自分時間を置きやすい曜日・時間帯の傾向が出る。`[D]`
- 傾向を使った提案には「最近の傾向から」の表示が付く。`[D]`
- 設定で傾向の利用をオフにすると、傾向に基づく提案は出ない。`[D]` `[U]`
- 本人が明示した基本時間・目標と傾向が矛盾したら、明示が勝つ。`[D]`

### S7 良くなったかを測る（週次ふりかえり）
- マイ余白タブに「今週のふりかえり」：自分時間（時間／週の目安）、提案の採用・見送り数、満足度（1タップ・3段階）。`[U]` `[UI]`
- 月をまたぐ週も、日ごとにその月の目標で目安を出す。`[D]`
- 満足度が「しんどかった」の翌週は、自分時間を少し多めに提案する。`[D]`

## 5. UI・UXゴール（代理指標）

| ID | 指標 | 判定 |
|---|---|---|
| U1 | S1: チャットで送信後、適用まで **1タップ**（「この案で置く」） | `[UI]` |
| U2 | 提案の適用・見送りで確認ダイアログを出さない（最終防衛・削除など既存の確認は維持） | `[UI]` |
| U3 | すべての提案に1行の理由が付く（空文字禁止） | `[D]` |
| U4 | ホームに同時に出す能動的提案は1件まで | `[U]` |
| U5 | 新しい画面・カードのスクリーンショットを CI で撮る | screenshots workflow |
| U6 | 見た目の最終判断 | **ユーザーのレビューゲート**（終了条件外） |

## 6. ループの運用

- 1イテレーション = 実装 → `scripts/test-domain.py` → `feature/time-ownership-v2` へ push → `iOS CI` の結果で修正。
- **完了:** S1・S2・S4・S6・S7 の全テスト＋既存テストが CI で緑、かつ U5 のスクリーンショットが取得でき、私がスクショを見て明らかな不具合がない時点。
- **打ち切り:** CI 10 回で未完なら止めて状況を報告する。
- **途中で止まってユーザーに聞く:** 原則に関わる判断、既存データの破壊的変更、新しい外部依存の追加、既存のチャットや再配置の振る舞いを変える必要が出たとき。
