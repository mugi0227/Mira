# Loop Goals — 「自分の時間の主導権を取り戻すAI」v0.1

**目的:** 構想まとめ v0.1 を、Claude がループ改善で「終わった」と判定できる形に落とす。
**判定者:** GitHub Actions `iOS CI`（build + unit + UI tests）と、Linux 上のドメインテスト。主観評価は終了条件に含めず、ユーザーのレビューゲートとして残す。

---

| 原則 | 決定 |
|---|---|
| PR-004 勝手に予定を変更しない | **維持。** Miraは提案する。適用はユーザーの1タップ。提案時は通知が来る（ChatGPT Dots / Grok のような能動的提案）。 |

## 2. 範囲

対象: S1〜S4, S6, S7。
対象外（次ループ）: S5 フォロー・空き枠減少通知（バックエンドが必要なため）、外部カレンダー連携。

## 3. 受け入れシナリオ（機能ゴール）

各シナリオはテストで判定する。`[U]` = Linux でも走るドメイン unit test、`[UI]` = XCUITest。

### S1 曖昧な意図から提案
- 「来週は自分の時間を増やしたい」を入力すると、来週の自分時間を増やす**提案カード**が出る。`[UI]`
- 提案には追加される余白の一覧と増える時間数がプレビューされる。`[U]`
- 「この案で置く」1タップで適用される。`[UI]`
- 提案の適用で `confirmed`（他者を含む予定）は1件も変更されない。`[U]`
- 未知の入力でも「分からない」で終わらず、選べる候補を返す。`[U]`

### S2 提案は勝手に適用されず、通知で知らせる
- 来週の自分時間が目標を下回ると、能動的な提案が `pending` で作られる。カレンダーは変わらない。`[U]`
- 新しい能動的提案があり、通知が有効なら通知を予約する。通知は1日1件まで。同じ内容の提案は重複させない。`[U]`
- 見送り（1タップ）は記録され、同じ提案を同じ週に再提示しない。`[U]`
- 適用済みの提案は履歴から1タップで取り消せる（追加した余白が消える）。`[U]` `[UI]`

### S3 他者の依頼による侵食を防ぐ（回帰）
- 既存の ProtectionEngine / 最終防衛のテストがすべて緑のまま。`[U]`

### S4 空き枠の共有とプライバシー
- ルール（期間・曜日・時間帯・最短長）から共有可能な空き枠を生成する。`[U]`
- 空き枠は確定予定・余白（自分時間）・基本時間と重ならない。`[U]`
- 相手向けプレビューと共有文には、どの予定タイトルも余白の種類名も含まれない。埋まっている時間は「予定あり」とだけ出る。`[U]`
- 共有画面に到達し、プレビューが表示される。`[UI]`

### S6 傾向に沿った提案
- 採用・見送りの履歴から、自分時間を置きやすい曜日・時間帯の傾向を出す。`[U]`
- 傾向を使った提案には「最近の傾向から」の根拠表示が付く。`[U]`
- 傾向の利用をオフにすると、傾向に基づく提案は出ない。`[U]`
- 本人が明示した基本時間・目標と傾向が矛盾したら、明示が勝つ。`[U]`

### S7 良くなったかを測る（週次ふりかえり）
- 週ごとに「自分時間の確保（時間・目標比）」「提案の採用数」「満足度（1タップ・3段階）」を表示する。`[U]` `[UI]`
- 満足度が低い週の翌週は、自分時間を増やす提案が優先される。`[U]`

## 4. UI・UXゴール（代理指標）

| ID | 指標 | 判定 |
|---|---|---|
| U1 | S1: テキスト入力後、適用まで **2タップ以内**（送信＋適用） | `[UI]` |
| U2 | 提案の適用・見送り・取り消しで確認ダイアログを出さない（最終防衛と削除は既存のまま） | `[UI]` |
| U3 | すべての提案に1行の理由が付く（空文字禁止） | `[U]` |
| U4 | 同時に表示する未処理提案は最大3件 | `[U]` |
| U5 | 新画面のスクリーンショットをCIで撮る（Mira タブ / 共有 / ふりかえり） | screenshots workflow |
| U6 | 見た目の最終判断 | **ユーザーのレビューゲート**（終了条件外） |

## 5. ループの運用

- 1イテレーション = 実装 → Linux ドメインテスト → `feature/time-ownership-loop` へ push → `iOS CI` の結果で修正。
- **完了:** S1〜S4・S6・S7 の全テスト＋既存テストが CI で緑、かつ U5 のスクリーンショットが取得できた時点。
- **打ち切り:** CI 10 回で未完なら止めて状況を報告する。
- **途中で止まってユーザーに聞く:** 原則に関わる判断、既存データの破壊的変更、新しい外部依存の追加。
