# Mira 生成画像スキン制作ロードマップ

**ステータス:** 後続フェーズへ明示的に延期  
**担当想定:** Codex / Work等、画像生成とファイル反映を長いループで実行できる環境  
**優先順位:** Grill-Me Q61〜Q82の機能実装・テスト完了後

## 決定

今回の機能実装では、画像生成による新しい猫アセット・背景・装飾の本制作を行わない。

理由は、以下を一つの制作ループとして回す必要があるため。

1. 同一キャラクターを複数ポーズで生成
2. UIに載せて視認性・邪魔にならない大きさを確認
3. 透過、余白、解像度、ダークモードを調整
4. Assets.xcassetsへ格納
5. Simulatorで実画面を撮影
6. 不統一な差分を再生成・差し替え

この工程は、機能実装と同時に中途半端に進めず、Codex等で専用タスクとしてまとめて行う。

## 後続フェーズの制作対象

### Pixel Cat 表情・状態差分

- idle
- happy
- thinking
- warning
- sleepy
- relieved
- celebrating
- sad / tired

### スキン候補

- Soft Minimal 改良版
- Pixel Cat 高品質版
- やさしい猫秘書（両者の中間）

### 補助アセット

- オンボーディング挿絵
- 空状態イラスト
- 警告・成功時のワンポイント
- 背景パターン
- スキン別の小型装飾

## 実装側の前提

- 機能コードは特定の生成画像に依存させない。
- `PixelCatView` とテーマトークンを差し替え口として維持する。
- 構造操作はSF Symbolsを使い、生成画像をナビゲーションアイコンの代替にしない。
- 生成画像が未完成でも、全機能・アクセシビリティ・テストが成立する状態を保つ。
- 画像は小さい表示でも判別でき、情報を隠さないこと。
- 同一スキン内でキャラクター造形、線、光源、色温度を統一すること。

## 完了条件

- 主要8状態のキャラクター差分が統一デザインで揃う
- 透過背景の実装用アセットが用意される
- Light / Dark双方で確認済み
- ホーム、予定入力、最終防衛、日程調整、オンボーディングでSimulator QA済み
- 既存のSwiftUI描画版へ安全にフォールバック可能

**原則:** 画像はMiraを使いたくなる魅力を高めるが、予定判断や余白保護の理解を邪魔してはならない。
